# PageValues leakage audit (PRD §2.2)

## Why this matters

`PageValues` is a very strong predictor in the Online Shoppers Purchasing Intention dataset, but it is a post-page-render session summary. It is therefore appropriate for **post-session/batch scoring**, while it can be a deployment-time leakage candidate if a prediction is required before the funnel has rendered.

## Method

The winning model from the main benchmark is retrained with:

- `PageValues` removed; and
- `PageValuePerProduct` removed as well, because it is directly derived from `PageValues`.

The same train/test split and random seed are used. For CV, a fresh preprocessing pipeline is fitted inside every fold using only that fold's training partition. The reported ablation test PR-AUC is evaluated once on the untouched held-out test set.

The numeric result is stored in `reports/pagevalues_ablation.json` and is regenerated by `scripts\train.bat`.

## Results

For the current regenerated run:

- With PageValues: held-out test PR-AUC **0.862**; leakage-safe CV PR-AUC **0.845 ± 0.009**.
- Without PageValues and `PageValuePerProduct`: held-out test PR-AUC **0.543**; leakage-safe CV PR-AUC **0.520 ± 0.021**.
- Held-out test PR-AUC gap: approximately **0.318**.

The generated JSON is the source of truth. It contains both:

- `metrics.cv_pr_auc_mean/std` — leakage-safe cross-validation performance without the two PageValues-derived inputs.
- `metrics.pr_auc` — held-out test PR-AUC without the PageValues signal.

Compare `metrics.pr_auc` with the selected model's held-out `pr_auc` in `models/training_metadata.json` to quantify the test-set PR-AUC gap.

## Deployment decision

- **Post-session/batch scoring:** keeping `PageValues` is reasonable because the value is available after the session pages render.
- **Pre-render online scoring:** remove `PageValues` and all directly derived features such as `PageValuePerProduct`, and retrain the deployment model.

This project keeps the PageValues model as the default because the API represents post-session session scoring. The audit is retained so the deployment trade-off is explicit rather than hidden.
